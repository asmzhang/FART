FART 脱壳使用方法
工作原理
刷入 FART ROM 后，脱壳由 ActivityThread 在应用启动时自动触发，通过读取配置文件 cyrus.config 来控制行为。

本地补丁树（按 Android 版本）：
  fart6 / fart8 / fart10 / fart_android-13.0.0_r4
均为「已改文件」overlay，缺基线时可从对应 AOSP tag 拉单文件再叠补丁。
日常用法见本文；android-13 的 <clinit> 行为见文末专节。

第一步：推送配置文件
在目标应用的私有目录创建配置文件：


adb shell
# 切换到 root
su

# 创建配置目录（如果目录不存在）
mkdir -p /data/data/<目标包名>/

# 写入配置文件
cat > /data/data/<目标包名>/cyrus.config << 'EOF'
dump=true
sleep=10000
EOF

# 修正权限（让应用自身可读）
chmod 777 /data/data/<目标包名>/cyrus.config
配置项说明
配置项	示例值	说明
dump	true	是否启用脱壳，必须设为 true
sleep	10000	启动后延迟多少毫秒再脱壳（建议 5000~30000，等待壳解密完成）
force	com.example.*	只主动调用匹配的类（支持 * 通配符，逗号分隔）
ignore	com.example.stub.*	跳过匹配的类，其余全部主动调用
is_fix	true	将捕获到的 CodeItem 回写到内存缓冲区，结束时写出 *_dex_file_fix.dex
init_classes	true	默认 true。巡检用 Class.forName(name,true,cl) 跑 clinit；false 则只 loadClass（不初始化）

示例（精确控制）：

dump=true
sleep=15000
force=com.target.app.*,com.target.lib.*

示例（排除不需要的类 + 内存修复）：

dump=true
sleep=10000
ignore=com.android.*,androidx.*,kotlin.*
ignore=com.luoye.dpt.junkcode.*
is_fix=true
第二步：启动目标应用

# 方式一：直接启动
adb shell am start -n <包名>/<主Activity>

# 方式二：手动点击图标启动
第三步：等待脱壳完成
通过 logcat 监控进度：


adb logcat -s ActivityThread:E | grep -E "sleep|Inspection"
关键日志顺序：

start sleep......10000 → 开始休眠等待
sleep over and start startCodeInspection → 开始主动调用
startCodeInspection run over → 脱壳结束
第四步：提取 dex 文件

adb pull /data/data/<目标包名>/  ./dump_output/
产物一般在 /data/data/<包名>/cyrus_<包名>/ ：
  dex_manifest.json       槽位/kind/location/checksum/pkg_match/inmemory
  loaders_<phase>.txt     发现到的 ClassLoader
  inspect_fail.txt        主动调用失败（VerifyError 等），不影响已 dump 的 DEX
  primary/ extra/ custom/ inmemory/ auto/
                          按来源区分；Java 登记时会再写一份到对应 kind 目录（与 manifest 对齐）
  *_dex_file.dex          兼容旧脚本的扁平副本（全量）
  *_ins_*.bin             兼容旧脚本的扁平 CodeItem
  *_class_list.txt        该类 DEX 的类名
  fix/<kind>/             is_fix 回写，同样有扁平副本

怎么分（人看，不自动丢）
  系统          不产出（/system /apex /vendor /dalvik-cache 等）
  app 原包      primary/，location 带 base.apk!classes*.dex，pkg_match=true
  split         extra/，location 带 split_*.apk
  壳            看 loaders 类名、location、class_list；仍完整 dump
  app 加密/解密  同一槽位 ins/fix 是还原体；新出现的 inmemory/ 常是解密后的副本
  自定义加载    custom/，无 pathList 的 CL 字段收获
  动态加载      extra/ 或 inmemory/，location 为 files/*.dex 或空路径
  compact/cdex  manifest.compact=true

模块
  Cyrus.java     配置
  CyrusDump.java ClassLoader 发现（含自定义）、登记、巡检；ActivityThread 只挂钩
  自定义 ClassLoader：无 pathList 时递归收获 DexFile/cookie/嵌套 CL，不 NPE

配置补充
  scan_parents=false     默认不扫父链（framework）
  extra_loaders=true     扫 split / ApplicationLoaders / 线程 CCL / 自定义字段里的 CL


注意事项
sleep 时间需根据壳的解密速度调整，太短会导致壳未完全解密就开始 dump
不写 force 也不写 ignore 时，默认对所有类主动调用
force 和 ignore 同时存在时，force 优先（见 Cyrus.java）
adb push 配置后若 log 报 EACCES：ROM 会 restorecon 再读一次；仍失败则 chown 到应用 uid 后再 restorecon
反射主动调用拿不到 <clinit>；巡检默认 forName 初始化类，CodeItem 在 ArtMethod::Invoke 退出时写入（见下节）


------------------------------------------------------------
android-13.0.0_r4：<clinit> CodeItem 捕获（本地补丁）
------------------------------------------------------------

背景
  旧逻辑在 Execute 入口对 <clinit> 只调 traceDexExecution：整包 DEX 按 begin
  地址 dump 一次，不写 *_ins_*.bin。Virbox 等壳常在解释执行窗口才解开 body，
  主动调用又反射不到 <clinit>，导致残留几乎全是类初始化方法。

改动约定
  只改 overlay 里已有 FART 插入点，AOSP 正文不改。新增代码一律用 //add ... //add end 包住。

改动文件（仅 overlay，不必整树；基线漂移时从 AOSP 拉单文件）
  fart_android-13.0.0_r4/art/runtime/interpreter/interpreter.cc
  fart_android-13.0.0_r4/art/runtime/art_method.cc
  fart_android-13.0.0_r4/art/runtime/native/dalvik_system_DexFile.cc
  fart_android-13.0.0_r4/libcore/.../DexFile.java
  fart_android-13.0.0_r4/frameworks/.../ActivityThread.java
  fart_android-13.0.0_r4/frameworks/.../CyrusDump.java
  fart_android-13.0.0_r4/frameworks/.../Cyrus.java

  AOSP 单文件基线（tag android-13.0.0_r4）：
  https://android.googlesource.com/platform/art/+/refs/tags/android-13.0.0_r4/runtime/interpreter/interpreter.cc
  https://android.googlesource.com/platform/art/+/refs/tags/android-13.0.0_r4/runtime/art_method.cc

行为
  1. dump=true 才打开 native 热路径（setFartDumpEnabled）。无配置的应用不会写 ins。
     在 Application.makeApplication / onCreate 之前启用，才能抓住启动期 <clinit>。
  2. ArtMethod::Invoke 退出：IsClassInitializer() 时 traceMethodCode。
     AOSP 13 热路径是 nterp/quick stub，C++ Execute 经常进不去；这是 <clinit>
     的主窗口（与 Frida 钩 Invoke leave 相同）。主动 dump 短路（g_fart_trace_active）
     不走这条，避免把未执行的占位体锁进 dumped set。
  3. Execute 仅退出 dump（RAII 析构；禁止入口 dump）。<clinit> 禁止从 C++ 解释器
     跳 compiled 占位。禁止 PrettyMethod()+strstr。热路径不写整包 DEX。
  4. 整包 DEX 由 Java 登记 / flushManifest 在 JNI 线程写出（kind 目录 + 扁平副本）
  5. 巡检默认 Class.forName(name, true, cl) 跑 <clinit>（loadClass 只链接不初始化）。
     init_classes=false 可关掉。getDeclaredMethods 仍然拿不到 <clinit>。
  6. traceMethodCode：按 (dex_begin, method_idx) 去重后追加写 *_ins_*.bin；
     仅 <clinit> 占位/打孔体（insns≤1、len≤18、return-void、const/4+return、高零比）
     不写、不进集，解密后可再进。
     is_fix 缓冲区在 nativeSetFixEnabled 时按 owned DEX 预填，热路径只 memcpy CodeItem
  7. CodeItem 追加路径不做 fsync；越界/损坏 handler 的 CodeItem 丢弃不写
  8. cyrus.config：打开失败时 SELinux.restorecon 再读；兼容 /data/data 与 /data/user/0
  9. 结束时写出 dump_stats.json（clinit_written / placeholder_skipped）和 inspect_stats.txt

编译 / 刷机
  将 overlay 覆盖进完整 AOSP 树对应路径后整编。android-13 带公开类
  android.app.Cyrus，整机 m / brunch 必须先关 metalava，否则编 framework 失败。

  每次新开终端都要 export（只对当前 shell 有效）：

  export WITHOUT_CHECK_API=true
  source build/envsetup.sh
  lunch aosp_redfin-userdebug
  m

  本轮同时改了 ART（libart / ART apex）和 framework / libcore。
  只推 framework.jar 不够：没有 Invoke 退出钩子，巡检跑了 <clinit> 也写不进 ins.bin。
  增量可先 m libart 再 m framework，AOSP 13 的 ART 在 com.android.art apex 里，
  整机 m + 刷 boot/system/apex 更稳。不要改 current.txt，dump ROM 用关检查即可。

刷机后验证
  # 清旧产物再跑目标包（不必再挂 Frida）
  rm -rf /data/data/<包名>/cyrus_*
  # 跑完后：
  cat /data/data/<包名>/cyrus_*/dump_stats.json
  cat /data/data/<包名>/cyrus_*/inspect_stats.txt
  grep "<clinit>" /data/data/<包名>/cyrus_*/*_ins_*.bin
  # dump_stats.clinit_written 应明显大于 0；记录里 code_item_len 应大于 18
  # 仍为 0 说明 dump 没打开、类没初始化、或仍是占位体

限制
  - 只捕获实际跑过的 <clinit>（forName 初始化 / 业务路径会跑；已初始化的类不会再跑）
  - 解密若发生在 Invoke 返回之后（ClassLinker 尾部），退出 dump 仍空，再钩 InitializeClass
  - init_classes=true 会执行类静态初始化，个别类 ExceptionInInitializerError 记入 inspect_fail
  - 广告/动态 DEX 里 ClassNotFound 的方法仍可能打孔，不是 VMP 缺口
  - traceDexExecution 仍保留但 Execute 不再调用（死代码，可留可删）


------------------------------------------------------------
AOSP API 检查（metalava）
------------------------------------------------------------
android.app.Cyrus 是公开类，AOSP 把它当成新增 SDK API。
不更新 frameworks/base/api/current.txt 就会 checkapi 失败。
dump ROM 不维护 current.txt：每次编译前必须

  export WITHOUT_CHECK_API=true

再 source / lunch / m。新开终端、环境被清掉后都要再 export。
